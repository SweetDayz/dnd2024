# /next：做下一個子任務

## 1. 找出要做的子任務

- 若使用者有給參數（`$ARGUMENTS`，例如 `M1-3`），就做那一個。
- 否則依序讀 `docs/tasks/M0.md`、`M1.md`、`M2.md`……，找出**第一個還有未勾選 `- [ ]` 項目的子任務**（以 `## M?-?` 或 `### M?-?` 標題為單位）。
- **跳過標示為「你自己做」的子任務**（例如 M0-1 到 M0-3）。如果它們還沒完成，先檢查能不能自動確認（例如 `node -v`、`git --version`、`CLAUDE.md` 是否存在）；確認不了就提醒使用者，然後跳到下一個可由 Claude 做的子任務。
- 確認前置條件：前一個里程碑的完成標準是否已滿足。沒滿足就告訴使用者，不要硬做。

## 2. 簡短計畫

用不超過 10 行列出：要做什麼、會新增或修改哪些檔案、怎麼驗收。結尾問一句「OK 就開始？」，等使用者回覆。

例外：若子任務只涉及新增文件或測試、不改既有程式碼，可以直接開始。

## 3. 實作

- 遵守 `CLAUDE.md` 的所有硬性限制，特別是 `file://` 可執行、執行期不發網路請求。
- 使用者不熟 Vue：每完成一段有意義的程式碼，用 2–4 句話說明「做了什麼、為什麼這樣做」。新概念第一次出現時，順手補進 `docs/guide/vue-primer.md`。
- 遇到需要使用者決定的事（資料與規則衝突、官方書目範圍等），寫進 `docs/data-notes.md` 的「待決事項」區，**先用合理預設值繼續**，最後一起問。

## 4. 驗收與收尾

1. 執行 `/verify` 的流程（讀 `.claude/skills/verify/SKILL.md` 照做）。
2. 驗收通過後，把該子任務的 `- [ ]` 改成 `- [x]`。
3. 用一個 commit 提交，訊息格式為 `feat(M1-3): 簡短描述`；不要自動 push，除非使用者要求。
4. 回報格式：
   - ✅ 完成了什麼（1–3 行）
   - 🧪 驗收結果
   - ❓ 待決事項（如果有）
   - ⏭️ 下一個子任務是什麼
