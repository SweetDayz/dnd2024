# /auto：自動跑完一個里程碑

使用者授權你在本次指令範圍內**不必每個子任務都等確認**。這覆蓋 `CLAUDE.md` §9「先 plan 再等同意」的規則，但只限於下面的停止條件之外。

## 開始前

1. 決定目標里程碑：`$ARGUMENTS`；若省略，就是第一個還有未勾選項目的里程碑。
2. 列出這個里程碑剩下的子任務清單，並用一句話說明你會依序做完。不用等回覆，直接開始。
3. 用 TaskCreate 建立任務清單，讓使用者在旁邊看得到進度。

## 迴圈

對每個未完成的子任務，照 `.claude/skills/next/SKILL.md` 的第 3、4 步做（實作 → 驗收 → 勾選 → commit），**但跳過第 2 步「等確認」**。

## 必須停下來的情況

遇到以下任一情況，就停止並回報，不要猜：

- 子任務標示為「你自己做」，而且無法自動確認是否已完成。
- `/verify` 連續失敗 3 次，自己修不好。
- 需要使用者做決定，而且沒有合理的預設值可用（例如會影響資料結構、之後很難改的選擇）。可以用預設值繼續的，就記進「待決事項」繼續做。
- 要刪除大量檔案、改寫 git 歷史、push 到遠端，或安裝 CLAUDE.md 沒提到的大型相依套件。
- 里程碑的「完成標準」全部達成：做最後一次完整驗收，然後停下來。

## 結束時回報

- 完成了哪些子任務（每個一行）
- 最終驗收結果
- 累積的待決事項（編號列出，方便使用者逐一回答）
- 下一個里程碑是什麼，以及開始前需要使用者先做的事（如果有）
