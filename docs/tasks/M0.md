# M0：本機開發環境＋專案骨架

> 本檔放在 `docs/tasks/M0.md`。前半段（M0-1 到 M0-3）由**你自己動手**，後半段（M0-4 起）交給 Claude Code。
> 以下以 **Windows** 為主，macOS 的差異另外附註。

## M0-1 安裝工具（你自己做）

| 工具 | 用途 | 安裝方式 | 確認指令 |
|---|---|---|---|
| Git | 版本控制 | https://git-scm.com 下載，安裝選項都用預設 | `git --version` |
| Node.js（LTS 版） | 執行 Vite、npm | https://nodejs.org 下載 LTS 安裝檔 | `node -v`（需 ≥ 22）、`npm -v` |
| VS Code | 編輯器 | https://code.visualstudio.com | — |
| Chrome | 驗收 `file://` 開啟 | 你應該已經有了 | — |

macOS 可以改用 `brew install git node`。

安裝完後，**重開終端機**，再跑一次上面的確認指令。

## M0-2 VS Code 擴充套件（你自己做）

在擴充套件面板（Ctrl+Shift+X）搜尋並安裝：

- **Vue - Official**（Vue.volar）：提供 `.vue` 檔的語法、型別檢查、自動完成。
- **ESLint**、**Prettier - Code formatter**：負責程式風格與自動格式化。
- **Claude Code**（Anthropic 官方）：安裝後依指示登入你的 Claude 帳號。

## M0-3 建立 repo（你自己做）

1. 在 GitHub 建立一個空 repo，例如 `dnd2024-cn-builder`，可設為私有或公開。
2. 在終端機執行：
   ```
   git clone https://github.com/<你的帳號>/dnd2024-cn-builder.git
   cd dnd2024-cn-builder
   code .
   ```
3. 把整包 `dnd-kit.zip` 解壓到 repo 根目錄。解壓後應該有 `CLAUDE.md`、`.claude/skills/`、`docs/tasks/`、`docs/ref/`、`docs/guide/`。注意 `.claude` 是隱藏資料夾，Windows 檔案總管要開「顯示隱藏的項目」才看得到。
4. 提交第一個 commit：`git add . && git commit -m "docs: project spec" && git push`

## M0-4 專案骨架（交給 Claude Code）

在 VS Code 開啟 Claude Code，輸入 `/auto M0` 就會自動跑完 M0-4 到 M0-6。想一步一步看的話，改用 `/next`。

Claude 要完成：

- [x] 用 `npm create vue@latest` 建立專案，選項為 TypeScript、Pinia、Vitest、ESLint、Prettier；**不選** Router，因為建角精靈用元件切換就夠了，之後需要再加。
- [x] 安裝 `vite-plugin-singlefile`，在 `vite.config.ts` 設定 `base: './'`。
- [x] 實作 classic-script 資料載入器（`window.__DND__.register` 搭配 Promise 化的 `loadData(kind)`），並用一份假資料 `public/data/demo.js` 示範。
- [x] 建立深色主題的 CSS 變數，首頁顯示「Hello DND」以及從 demo 資料讀出的一行字。
- [x] 在 `package.json` 準備以下 scripts：`dev`、`build`、`test`、`lint`、`fetch-data`（先放空殼）、`build-data`（先放空殼）。
- [x] 設定 `.gitignore`，排除 `node_modules`、`dist`、`raw`。
- [x] 安裝 Playwright（只裝 Chromium：`npx playwright install chromium`），撰寫 `scripts/check-file.mjs`：以 `file://` 開啟 `dist/index.html`，收集 console error 與未處理的 promise rejection，並做簡單的 smoke check（例如畫面上有「Hello DND」）。有錯誤就以非零結束碼退出。在 `package.json` 加上 `check:file` script。這是讓 `/verify` 能自動驗收、你不用每次手動開檔的關鍵。

## M0-5 認識這個專案（交給 Claude Code）

請 Claude 寫一份 `docs/guide/vue-primer.md`，**用這個專案的實際檔案當例子**，說明：

- 各資料夾與檔案的用途；`npm run dev` 和 `npm run build` 的差別。
- `.vue` 單檔元件的三段結構（`<script setup>`、`<template>`、`<style>`）。
- `ref`、`computed`、`v-for`、`v-if`、`v-model`、props 與 emit 的最小範例。
- Pinia store 是什麼，以及規則引擎為什麼要寫成純 TS、不放進元件。
- 如何寫和執行一個 Vitest 測試。
- 常見問題：為什麼雙擊 `index.html` 會白畫面，要怎麼排查。

## M0-6 驗收

- [ ] `npm run dev`：瀏覽器開 `http://localhost:5173`，畫面正常；修改 `.vue` 檔後畫面會即時更新。
- [ ] `npm run build` 後執行 `npm run check:file` 通過；你也親自雙擊 `dist/index.html` 確認一次畫面正常、Chrome 主控台（F12）零錯誤。之後的里程碑就交給 `check:file` 自動驗收。
- [ ] `npm test`：至少一個測試通過，例如資料載入器的測試。
- [ ] commit 並 push。
