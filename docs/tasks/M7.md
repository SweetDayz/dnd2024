## M7-2 BUG 盤查：魔法物品混入工具熟練選項（停下來問）

使用者回報：吟遊詩人的「工具熟練（選 3）」除了一般樂器，還列出 +1 调律者之鼓、吟游诗人乐器、瓦尔哈拉号角、爆破号角、塞壬之歌里拉琴等魔法物品。使用者擔心這只是同一個根本問題的其中一個症狀，所以**先查清楚，再修正**。

- [x] 找出根本原因：工具熟練的選項清單從哪裡產生、用什麼條件篩選。推測是依物品類型代碼篩選了包含魔法物品的資料，但一切以程式碼和資料為準。
- [x] 盤點所有「從物品資料依類型或分類產生選項」的地方，至少檢查以下幾處，以及其他呼叫相同查詢函式的地方：
  - 工具熟練：任一樂器、任一工匠工具、任一遊戲套組、任一工具。來源包含職業、背景、種族、專長、兼職熟練。
  - 起始裝備的 `equipmentType`，例如任一簡易武器、軍用武器、工匠工具、樂器、法器。
  - 武器精通（Weapon Mastery）的可選武器。
  - 武器篩選型熟練（武僧、遊蕩者，見 `docs/handoff.md` §6）。
- [x] 每一處都用實際資料統計：目前列出幾項、其中幾項是魔法物品或其他不該出現的項目，並舉例。
- [x] 檢查既有存檔：如果玩家已經把魔法樂器選為工具熟練，修正後要怎麼處理。
- [x] 以上結果寫進 `docs/data-notes.md` 新的一節，並附上修正方案。預設方案如下：
  - 建立一個共用的「一般物品」判斷函式，依資料欄位判斷（例如稀有度、是否為基礎物品）。實際用哪些欄位，**以調查結果為準**。所有選項清單都改用這個函式。
  - 已啟用書目中的一般異域樂器（例如 SCAG 的各種樂器）保留，因為它們是一般工具，不是魔法物品。
  - 既有存檔裡變成不合法的選擇，改顯示為「未選擇」，並在審卡報告的警示區提示。不升級 `schemaVersion`。
- [x] **停下來問**：把盤點表摘要給使用者看，等使用者同意修正方案後，才開始 M7-3。

## M7-4 兼職修正

使用者回報的症狀：**在建角流程中加不了第二職業**。目前 `check:file` 只走單一職業，兼職只有規則引擎的單元測試，UI 流程可能從來沒有被端對端測過。

- [x] 用 Playwright 從空角色經 UI 重現「加不了第二職業」：建立法師並升到 2 級以上，再嘗試加入牧師。把以下內容記錄到 `docs/data-notes.md`：
  - 加入職業的入口在哪裡，或是否根本沒有入口。
  - 按下後的反應、console 錯誤、截圖。
  - 根本原因。可能的方向：入口沒顯示、前置條件判斷錯誤而把所有職業都擋掉、選了之後狀態沒寫入。一切以實際查到的為準。
- [x] 修正後，用以下**第二驗收角色**驗收：
  - 組合：法師 3／牧師 2，起始職業為法師，屬性用標準陣列，智力與感知都 ≥ 13。
  - 總等級 5，熟練加值 +3。
  - 施法者等級 5，法術位 4/3/2。
  - HP = 6（法師 1 級滿值）＋ 4 × 2（法師 2、3 級取平均）＋ 5 × 2（牧師 2 級取平均）＋ 5 × 體質調整值。
  - 兼職牧師獲得的熟練，依資料的 `multiclassing` 欄位。
  - 兩個職業的戲法數、準備法術數，各自依該職業的職業表計算。
  - 法術 DC 與攻擊加值分別用智力和感知計算。
  - 前置條件：把感知改成 12 時，牧師選項反灰並顯示原因。
- [x] 規則引擎再加一組契約魔法的測試：魔契師 2／術士 3。預期契約魔法有 2 個 1 環法術位，一般法術位為 4/2，兩者分開顯示。

## M7-5 錢幣重量與負重狀態

使用者決定：**只用 2024 規則**，不做 2014 的變體負重（Encumbrance）規則，也不做它的開關。

- [x] 先從資料找出以下規則的原文，記錄到 `docs/data-notes.md`，**不要憑記憶**：
  - 錢幣重量（XPHB）。
  - 負重上限 Carrying Capacity（XPHB 規則詞彙），以及不同體型的倍率。
  - XPHB 中超過負重上限，或在推、拖、舉重物時，對速度或擲骰的影響。
- [x] 錢幣計入總重量：
  - 依原文換算各幣別，加總後計入。
  - 物品頁的重量明細另列一行「錢幣」。
- [x] 物品頁顯示負重條：目前總重、負重上限，以及 XPHB 原文規定的其他門檻（例如推、拖、舉的上限，若原文有）。超過上限時要明顯標示，並附上原文效果。
- [x] 若 XPHB 原文規定超重會影響速度，角卡的「速度」欄位顯示扣減後的數值，旁邊放小圖示說明原因。若原文沒有規定速度扣減，就只標示超重，不要自行加上減速。
- [x] 超重狀態要加進 M6 審卡報告的警示區。
- [x] Vitest 要涵蓋：
  - 錢幣重量換算。
  - 各門檻的邊界值：剛好等於、超過一點。
  - 小型與中型體型。
  - 若有速度扣減，扣減前後的速度。
- [x] `check:file`：讓基準角色身上加入大量金幣，使總重超過上限，檢查畫面出現超重標示。

參考 5e.kiwee.top 的語言頁。它的表格欄位有名稱、英文名、類型、文字、來源，上方有來源篩選。

- [x] 資料瀏覽器新增「語言」分頁：
  - 可排序表格，欄位為名稱、英文名、類型、文字、典型使用者、來源。

- [x] 建角精靈的語言選擇改用同一個表格。依 2024 規則處理：

## M7-7 物品：分表、排序與篩選

參考 5e.kiwee.top 的物品頁：一般物品和魔法物品分成兩個表，篩選項有稀有度、物品屬性、同調、分類、花費範圍、重量範圍。

- [x] 資料瀏覽器的物品分頁，以及角卡或建角流程中「新增物品」的選單，改用同一套表格與篩選。
- [x] 分成兩個表，一般或魔法的判斷沿用 M7-3 的共用函式：
  - 一般物品：名稱、英文名、類型、價值、重量、來源。
  - 魔法物品：名稱、英文名、類型、重量、同調、稀有度、來源。
- [x] 各欄都可排序。價值與重量要依數值排序，不是依字串。
- [x] 篩選沿用 M5 的三態篩選面板，包含「全選／清除」與 AND／OR：
  - 來源、類型、稀有度。
  - 物品屬性（雙手、多用、彈藥、靈巧、輕型、重型、觸及、投擲、裝填等）：依資料的屬性代碼產生，不要寫死清單。
  - 武器精通（2024）。
  - 同調，分三類：需要同調、需特定條件才能同調、不需要同調。條件細項（種族、職業、陣營等）不做成篩選項，只在詳情中顯示原文。
  - 分類（基礎、通用變體、特定變體、其他）：**先調查管線是否有產生變體物品**（例如 +1 板甲）。若沒有，這一組只顯示資料中實際存在的分類，並把「是否納入魔法變體」記到待決事項，M7 不擴充資料。
  - 價值範圍、重量範圍：用兩個數字輸入框即可，不必做滑桿。
- [x] 篩選狀態比照 M5 的 UI 偏好存法。
- [x] Vitest：篩選純函式（屬性、同調、範圍、AND／OR），以及數值排序。
- [x] `check:file`：
  - 物品分頁篩選「稀有度：珍稀」後，只剩魔法物品表，且每一列的稀有度都是珍稀。
  - 依價值排序後，第一列的價值最低。
